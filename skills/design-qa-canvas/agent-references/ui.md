# How the canvas UI is built (read only when changing template/)

- `build.py` inlines `styles.css` + `canvas.js` into `body.html` and embeds the issues as `<script id="qa-data" type="application/json">`. No framework, no network.
- `canvas.js` state `S`. `load()` reads the embedded data, then every `api/*` store, and applies edits, section renames, accepted/removed suggestions, removed issues and read state.
- Every write goes through `post(url, body)` with `X-Actor: User`. Offline, writes queue in `localStorage` (`qa-outbox:<path>`) and flush when the server is back.
- `refresh()` polls comments + inbox every 3 s and re-renders, unless the user is typing or editing. Live reload uses `/api/version` (page mtime) and restores pan, zoom, selection and tab.
- Pan/zoom: CSS transform on `#world`. `paint()` is batched with requestAnimationFrame (rAF). Zoom keeps the item under the cursor fixed across reflows (`reanchor`). Zoom range: min = everything fits, max = 800%. Pan has no bounds. Gestures lock to vertical unless clearly sideways.
- Card layout v2: sizes are tied to the screenshot width via container units so that at the 0-key zoom the heading is 24px, details 20px and corners 12px on screen (`--zw`, set by `setZW()`, is the width the screenshot gets at that zoom); text scales with zoom and never re-wraps. Image buttons keep their own fixed screen size (`--acs`). Issue row = number, priority, unread dot, title, inline "Details ⌄" (details collapsed by default); menu/delete/comment show on hover (on the screenshot for a single card, at the row's right in a shared card). A shared card holds at most 4 issues (`MAXG`); more continue on another card with the same screenshot. Details clamp at 4 lines, then "Show more"; expanding one card lets its row-mates use the space.
- API (server.mjs): `GET/POST /api/priorities`, `/api/state` (read), `/api/edit` (`{cid,title|what|out}` or `{section:{from,to}}`), `/api/suggestions`, `/api/removed` (+ `/purge`), `/api/inbox/:id` (`processed`, `deleted`, `resolved`), `/api/comments` (+ `/:id/reply`, `/:id/flags`), `/api/version`.
- Browser test pattern: headless Chrome via the DevTools protocol (`--remote-debugging-port`, `node --experimental-websocket`). Dispatch real mouse and key events, then assert on `S` and on computed styles. Headless ⌘-click is unreliable; test it with a synthetic `MouseEvent`.
- **Flow mode** (`workflow-canvas` skill): set when the data has `steps`. `flowLayout()` builds the effective graph: a removed step's preds connect to its succs, and a removed origin just drops. It then finds connected components (= flows), longest-path depth (= column) and order. `drawArrows()` draws SVG cubic arrows plus horizontal labels per `.fl` after every render, fit and image load. Read state is keyed `id@<sha1(img)[:8]>`, so a replaced screenshot is unread again. `prev` adds a Compare toggle. The Issues tab and Sort are hidden.
- Side pane: a sticky bulk bar with no background sits at the top of the list. New tab: Mark all read / Mark all unread (toast with Undo). To-dos: Resolve all · N (threads Claude finished), which asks first in a modal (`confirmBox`) and then offers Undo. The watcher line shows only when a watcher is off. Ctrl+wheel (trackpad pinch) outside the canvas is blocked so the page never zooms and hides the panels; Cmd +/- browser zoom still works.
- Flow mode: each flow's heading (`.lane h2 .lt`) is a soft primary blue. First steps (no incoming arrow) carry `.fstart`, unstyled.
- To-dos has sub-tabs Completed · In progress · Resolved (each hidden when empty). Resolved is a read-only reference loaded from `?all=1`, with per-thread delete and Delete all (confirm), both with an 8s Undo. The comment popover shows a "Resolved · n" toggle only when that screen has resolved threads. New tab rows carry the comment marker (blue when Claude replied last); marking a New row read selects the next new item.
- Resolving a thread from the To-dos list (✓ on a task) opens the next task's popover and zooms to its screenshot (`openNextTask`), so review is one click per thread.
- Tabs: QA = Issues · New · To-dos · Deleted; workflow = Screens (the Issues tree, by flow) · New · To-dos (opens first) · Deleted. To-dos (formerly Inbox) uses the comment-check icon. Side pane collapses from the icon left of the title (`#sbcol`, `#sbopen` brings it back). Priority badges: Settings → Priority; default shown on QA, hidden on workflow (`html.noprio`). New rows have menu + chat like Issues rows. Deleted rows show a thumbnail; click opens it in the lightbox (deleted items never sit on the canvas). Space on the New tab walks the New list.
- Settings (labels above controls): Numbers · Canvas (swatches + hex box; shorthand f→FFFFFF, f4→F4F4F4, abc→AABBCC) · Screen switch (Auto: slide, quick repeats instant · Pan · Instant; `S.anim`) · Priority · Titles. Keyboard button by the zoom controls opens the shortcut list (`kbList`). Alt flips the selected card (QA: `ref` design reference, shown as "Design"; workflow: `prev`). The watcher warning sits above the icon row with Copy message and Copy with skill setup.
